# Модель безопасности KeenWG 2.x

## Границы доверия

Companion слушает один конкретный приватный IPv4-адрес роутера на HTTPS-порту `18779`. Wildcard, loopback, публичный адрес, hostname, URL с userinfo, query или fragment отклоняются конфигурацией. Публичный/WAN listener не поддерживается.

Android получает host key до отправки пароля. Для нового профиля используется trust-on-success: key сохраняется только после успешной установки, HTTPS-проверки и выдачи токена телефону, поэтому первую настройку нужно выполнять в доверенной локальной сети. Уже сохранённый key сравнивается до авторизации; его изменение блокирует отправку пароля и требует отдельного подтверждения сброса или замены роутера. Адрес первичной настройки, host key, точный SHA-256 pin сертификата и токен телефона сохраняются одной транзакцией профиля; адрес Keenetic API хранится отдельно. Системные и пользовательские CA не заменяют pin.

Companion обращается к KeeneticOS через локальный `ndmq` и только по фиксированному списку команд с ограничением времени и размера ответа; произвольная shell-команда из API невозможна. RCI оставлен только как legacy-путь для профиля без Companion. Необязательный Collector является отдельным read-only модулем. Его cleartext HTTP допустим только внутри доверенной LAN или уже настроенного WireGuard и не должен публиковаться в WAN.

## Pairing и права

- Одноразовое приглашение имеет короткий TTL и scope `viewer`, `operator` или `owner`.
- После обмена телефон получает собственный случайный токен; на роутере хранится только его SHA-256.
- `viewer` читает разрешённые данные, `operator` выполняет сетевые операции, `owner` управляет устройствами, приглашениями и backup.
- QR не содержит owner token. Закрытие экрана отзывает неиспользованное приглашение.
- Истёкший, повторно использованный или отозванный credential отклоняется.
- Последнего owner нельзя отозвать.

## Секреты

Android шифрует сохранённые пароли Keenetic API, device tokens, Collector token и конфигурации через Android Keystore/AES-GCM. Backup приложения отключён. Пароль установки вводится один раз, принадлежит активному Setup ViewModel, передаётся в операции только копиями и стирается при успехе, ошибке, отмене или уничтожении ViewModel. В профиль он не записывается.

Subscription URL, VLESS URI, UUID, Reality key, short ID, SNI и сырой Xray-конфиг остаются на роутере. Приватный ключ нового WireGuard-доступа создаётся и проверяется на Android, хранится только в зашифрованном хранилище телефона и никогда не отправляется Companion. API возвращает только нормализованные публичные поля, состояние операции и санитизированные ошибки.

На роутере identity, token hashes и pairing hashes находятся под `/opt/etc/keenwg` с закрытыми правами. Plaintext pairing secret возвращается один раз и не хранится в device store.

## Изменения и восстановление

Сетевые изменения требуют явного действия пользователя. Запрос содержит state version и, где нужна безопасная повторяемость, idempotency key. Результат имеет одно из состояний: `committed`, `rejected`, `rolled_back` или `uncertain`; успех по тайм-ауту запрещён.

Перед применением Companion проверяет candidate, выполняет Xray test/restart и read-back. Изменения статических DHCP-адресов и WireGuard сначала проходят review с точной версией состояния, затем отдельный apply, сохранение KeeneticOS, повторное чтение и проверяемый откат. При подтверждённой ошибке восстанавливается прежнее состояние; неопределённый результат не выдаётся за успех. Recovery-файлы принадлежат root, имеют режим `0600` и сохраняются при неопределённом результате.

Установка использует staging, SHA-256 bundle, self-check, HTTPS health и атомарное переключение release. Обновление 1.0 → 2.0 сохраняет identity, device store, активный маршрут и пользовательские данные. Устаревший самостоятельный сервис удаляется только после успешной проверки Companion 2.0 по фиксированному allowlist; каталоги Xray/XKeen и пользовательские правила в него не входят.

## Импорт, экспорт и отчёты

- VLESS, subscription, WireGuard и JSON проходят строгие ограниченные парсеры; неизвестные поля и превышение лимитов отклоняются.
- WireGuard-конфигурация открывается после подтверждённой записи и экспортируется через неэкспортированный cache-only FileProvider.
- Owner backup использует scrypt и AES-256-GCM, ограничен 4 МиБ, содержит SHA-256 записей и требует точный подтверждённый plan ID для восстановления.
- Support TXT/JSON редактирует токены, ключи, URL, UUID, hostnames, MAC и полные IP и создаётся только вручную.

## Что нельзя публиковать

Пароль доступа к роутеру, device/Collector token, pairing secret, subscription URL, VLESS URI, private WireGuard key, router backup и полный QR. Для issue используйте только санитизированный отчёт.
