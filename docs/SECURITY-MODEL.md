# Модель безопасности KeenWG 1.0

## Граница доверия

Companion слушает только конкретный локальный IP роутера. Wildcard `0.0.0.0`, публичный hostname и URL с userinfo/query отклоняются. Доступ предполагается из домашней LAN или через уже настроенный WireGuard.

Legacy HTTP API допускается только на приватном IPv4 во время миграции и защищён отдельным длинным bearer token. Новые устройства используют HTTPS API companion. Локальные API sing-box и AWG Manager принимаются только на loopback; внешний или wildcard-адрес считается ошибкой конфигурации.

HTTPS использует локальную identity companion. Android сохраняет точный SHA-256 pin сертификата и не доверяет системным или пользовательским CA вместо него. Изменившийся pin и изменившийся SSH host key приводят к отказу до авторизации или API-вызова.

## Pairing и права

- Bootstrap создаёт одноразовое owner-приглашение с TTL пять минут.
- После обмена телефон получает отдельный случайный token; на роутере хранится только его SHA-256.
- Scope: viewer читает доступные данные, operator может выполнять разрешённые операции, owner управляет устройствами и приглашениями.
- QR нового телефона содержит URL, certificate pin, offer ID, одноразовый secret и expiry. Owner token в QR отсутствует.
- Закрытие QR отзывает offer на сервере; повторный обмен, истёкший offer и отозванный token отклоняются.
- Последний owner не может быть отозван. Текущий телефон требует дополнительного подтверждения, после успешного отзыва локальная identity очищается.

## Хранение секретов

Android шифрует пароли, device tokens, legacy tokens и конфигурации через Android Keystore/AES-GCM. Backup приложения отключён. SSH-пароль живёт только в mutable byte buffer одной операции, очищается после соединения и не сохраняется в профиле.

Экспорт резервной копии создаётся только owner-устройством, шифруется AES-256-GCM с ключом scrypt, ограничен 4 МиБ и содержит SHA-256 каждого ресурса. Пароль копии не сохраняется. Предпросмотр возвращает только идентификаторы и размеры; восстановление требует точный проверенный plan ID. Временный экспорт через FileProvider остаётся зашифрованным.

На роутере identity, хэши токенов и хэши pairing secret находятся под `/opt/etc/keenwg` с закрытыми правами. Plaintext pairing secret возвращается один раз и не записывается в store.

## Изменения и восстановление

Установка использует staging, проверенный SHA-256 bundle, фиксированные команды и commit после проверок. Управляющие API используют state version и идемпотентные идентификаторы там, где операция может пережить потерю ответа. Ошибка обозначается как committed, rejected, rolled back или uncertain; «успех по таймауту» запрещён.

Companion не считает существующие конфиги XKeen/Xray/WireGuard своей собственностью. Обновление и удаление не должны удалять чужие ресурсы.

Recovery-файлы принадлежат root и имеют режим 0600. После подтверждённого результата они удаляются; при неопределённом результате сохраняются для ручного восстановления. Очистка, revoke, rotation, upgrade, restore и uninstall никогда не запускаются автоматически.

## Поверхности импорта и экспорта

- VLESS, WireGuard и JSON разбираются строгими ограниченными парсерами; неизвестные поля и неподдерживаемые варианты отклоняются.
- Подписка ограничена размером и количеством узлов до разбора. Ошибки содержат только стабильные коды и не включают входную строку.
- WireGuard-конфигурация показывается один раз после подтверждённой записи; незавершённая конфигурация хранится шифрованно до явного восстановления.
- Support TXT/JSON проходит редактирование секретов и экспортируется только по явному действию пользователя.
- FileProvider не экспортирован и открывает только выделенные cache-пути `confs/`, `support/` и `backup/` с временным read grant.

## Что нельзя публиковать в issue

SSH-пароль, admin password, device token, pairing secret, collector/XKeen token, subscription URL, VLESS URI, приватный WireGuard key и полный QR. Используйте только санитизированный отчёт.
